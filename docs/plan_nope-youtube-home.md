# YouTube 推薦面ブロック再設計（plan: nope-youtube-home）

YouTube の発信元ブロックを、利用者が実際に選別したい推薦面へ置き直す工程。
旧 `nope-v2` は検索結果と視聴ページの関連動画を対象にしたが、実利用で次が判明した。

- 検索結果はブロック済みデータを適用できる一方、利用者が発信元を登録する入口が無い
- 視聴ページの関連動画は見たい動画である可能性が高く、発信元ブロックの主対象ではない
- 旧テストは storage へブロック済みデータを直接投入し、登録から解除までの利用者導線を検証していなかった
- YouTube ホームは未ログイン調査だけで対象外にされ、ログイン済みの実DOMを確認していない

本工程では、**ホームの推薦フィードを主対象、検索結果を同じ操作の副対象**とし、視聴ページの関連動画から Nope の介入を撤去する。

## 成功条件

1. YouTube ホームの動画カードで、hover または keyboard focus 時に「このチャンネルをブロック」が現れる
2. ブロックは表示名ではなく `/@handle` または `/channel/UC...` から得た安定識別子で保存する。同一チャンネルに2形式が混在する場合の正規化は実DOM調査で決め、片方だけ再出現する状態を許さない
3. 操作直後、同じチャンネルのホームカードがリロードなしでブロックされる。無限スクロールと SPA 遷移後に追加されたカードにも効く
4. YouTube 検索結果にも同じブロック操作を置き、ホームと同じブロックリストを共有する。一方で登録したブロックが他方にも反映される
5. プレースホルダー表示時は元カードの高さを保ち、解除ボタンと popup の双方から復元できる
6. 視聴ページの関連動画はフィルタせず、Nope のボタンやプレースホルダーも出さない
7. 自動テスト、再パッケージ、展開版の実Chrome smoke を通す。実Chrome受入はオーナーのログイン済みYouTubeでホームと検索を確認する

## タスク

### yt-dom-survey — ホーム・検索の実DOM調査

ログイン済みまたは内容が表示される実YouTubeで、ホームと検索のカード境界、チャンネルリンク、安定識別子、hover/focus の差込位置、SPA遷移、無限スクロールを実測する。既存 fixture からDOMを推測しない。結果を `docs/survey/youtube-home-search.md` に残す。

### yt-flow-audit — 旧導線と対象面の監査

現行の manifest、共通エンジン、YouTube adapters、storage、popup、tests を追跡し、検索で登録入口が無かった理由と、関連動画ボタンが現れなかった理由を特定する。ホーム・検索・視聴ページそれぞれの正しい介入範囲を `docs/evidence/youtube-flow-audit.md` に残す。

### yt-contract-tests — UI契約と失敗テスト

`yt-dom-survey` と `yt-flow-audit` の実測を統合し、カード契約、識別子の正規化、即時反映、解除、SPA追従、負の範囲を `docs/design-youtube-surfaces.md` に確定する。実DOMから縮約した fixture で、実装前に失敗する受入テストを作る。

### yt-home-search — ホーム＋検索の共通ブロック導線

ホームと検索に共通のチャンネルブロック操作を実装する。安定識別子、即時反映、共有リスト、プレースホルダー、解除、SPA・無限スクロール追従を満たす。変更範囲は YouTube の推薦面とその共通処理に限定する。

### yt-watch-retire — 関連動画への介入撤去

視聴ページ用 adapter と content-script 登録を撤去し、関連動画をフィルタしない状態にする。README、ストア説明、プライバシー説明、提出資料に残る旧対象面の記述を、新しい面構成へ合わせる。

### yt-package-smoke — 自動検証・再梱包・実Chrome受入

関連テストと全テストを実行し、`dist/chromeblocker-v2.0.0.zip` を再生成する。展開版をChromeへ読み込み、オーナーのログイン済みYouTubeで次を実測する。

- ホームで登録・ブロック・高さ維持・解除
- 検索で同じ登録・ブロック・解除
- ホームと検索をまたぐ共有リスト
- SPA遷移と追加カードへの追従
- 視聴ページの関連動画に Nope のUIもフィルタも無い

実Chrome受入はオーナー操作を要する H 条件であり、その手前の自動検証と配布物作成は席が完了させる。

### yt-terminal-audit — 別席による終端監査

実装席とは別の席が diff、テスト、配布物、実Chrome証跡を監査する。特に「storage直投入だけの偽受入」「表示名IDへの退行」「関連動画への介入残存」「ホームだけ／検索だけに効く分断」を反証し、円卓へ受理または異議を報告する。

## 依存

- `yt-contract-tests` ← `yt-dom-survey`・`yt-flow-audit`
- `yt-home-search`・`yt-watch-retire` ← `yt-contract-tests`（並列）
- `yt-package-smoke` ← `yt-home-search`・`yt-watch-retire`
- `yt-terminal-audit` ← `yt-package-smoke`

## この工程の外にあるもの

- 視聴ページの関連動画に対する発信元ブロック、キーワードブロック、並び替え
- YouTube ホームに対するキーワードブロック
- チャンネル表示名だけを識別子にする互換処理
- YouTube 以外のサイトの機能変更
- Chrome Web Store への提出と公開（`chromeblocker-release/r7-submit` の外部条件が整うまで行わない）

## 既知の罠

- fixture を実装者の想像で作ると、実DOMの誤解まで再現して green になる。調査席の実測を先に正本化する
- YouTube は同一チャンネルを handle と UC ID の別形式で露出しうる。正規化不能を表示名マッチでごまかさない
- ログアウト状態のホームが空なら、到達不能を成功扱いにせず H 条件としてオーナーの通常Chromeへ渡す
- DOM差し替えと無限スクロールは初期ロードだけのテストでは検出できない
- 旧関連動画 adapter のコードを消すだけでなく、manifest と公開説明から対象面の主張も消す
